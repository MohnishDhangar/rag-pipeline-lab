# RAG Pipeline Lab

Experimental scientific RAG platform for physics-informed neural networks,
graph neural networks, PDE solvers, and scientific simulation research papers.

The goal is **evidence-grounded answers with an evaluated cost-aware retrieval
router**, not another generic document chatbot. The 63-question historical
benchmark is a starting point, **not evidence of a measured performance win**.

## Architecture

- **Embeddings:** Gemini embedding-001 (requires GOOGLE_API_KEY).
- **GPT generation and judging:** official Sign in with ChatGPT open-source
  OAuth and supported streaming Responses API requests. No Groq or local LLM.
- **Retrieval:** Chroma dense, optional PyLate/ColBERT, optional local scientific
  evidence graph blended with Reciprocal Rank Fusion.
- **RAG strategies:** naive, multi-query, RAG Fusion, HyDE, decomposition,
  step-back, RAPTOR indexing and corrective RAG.
- **Adaptive router:** an inexpensive, locally trained scikit-learn classifier
  selecting among existing strategies, with safe naive fallback.
- **Evaluation:** exact retrieved-context traces, source provenance, deterministic
  paper-level retrieval metrics, resumable custom GPT judging, optional RAGAS.
- **Demo:** Streamlit dashboard with source inspection and experiment comparison.

## Install and authorize GPT

Python 3.10 or later. In a terminal on your own computer:

~~~bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[rag,dev,dashboard]"
python -m pytest -q
python -m rag_lab.llms.cli login
python -m rag_lab.llms.cli models
~~~

On Windows activate the environment using .venv\Scripts\activate.

First sign-in registers the local open-source client in your browser.
You must approve ChatGPT plan usage. The callback binds to 127.0.0.1,
uses PKCE + state + nonce, validates the OpenID Connect ID token, and
stores protected access/refresh tokens outside the Git repository.
Use the --new-account login option if you want to authorize another account.
Model choices are specific to your authorized ChatGPT account.

Select a listed model slug and supply only the Gemini embedding credential:

~~~bash
export RAG_GPT_MODEL="model-slug-from-the-models-command"
export GOOGLE_API_KEY="your-google-embedding-credential"
python -m rag_lab.llms.cli test
~~~

On PowerShell set environment variables with $env:RAG_GPT_MODEL and
$env:GOOGLE_API_KEY instead.

Subscription usage is **not unlimited**. ChatGPT Plus plan usage is shared
across participating apps. This uses official OAuth, not scraped browser
cookies, unofficial ChatGPT routes, or a paid OpenAI API key. If permission
is refused, model access is unavailable, or a usage limit is reached,
the pipeline stops rather than bypassing restrictions.

## Prepare the corpus and local indexes

The PDFs and indexes are intentionally not included in Git. Place authorized
PDF copies in data/papers, then use notebooks/01_foundation.ipynb to build
data/chroma_naive_gemini. For ColBERT first export chunk texts and source metadata **together** using:

~~~bash
python -m rag_lab.retrieval.export_colbert_leaves --root .
~~~

Then run the index builder from notebooks/08_colbert.ipynb, adjusting its
environment-specific interpreter path. It produces data/colbert_index,
data/id_to_text.json and uses the aligned data/id_to_metadata.json
generated by the exporter. Rebuild the index if the corpus changes. The original notebooks contain some stale paths.

Build the optional source-linked evidence graph offline, without GPT calls:

~~~bash
python -m rag_lab.knowledge.build_graph --papers data/papers \
  --eval eval/eval_set.json --output data/evidence_graph.json
~~~

This initial graph links document passages with recognized research concepts
and source metadata. It is **not** an independently fact-checked causal
knowledge graph and PDF text extraction may lose mathematical layout.

## Generation

~~~bash
# Small GPT smoke test: three queries, one strategy
python -m rag_lab.evaluation.generate --strategies naive --backends dense --limit 3

# Resumable six-strategy benchmark, provided both indexes exist
python -m rag_lab.evaluation.generate --strategies naive multi_query \
  rag_fusion hyde step_back decomposition --backends dense colbert

# Optional scientific evidence graph retrieval
python -m rag_lab.evaluation.generate --strategies naive --backends dense \
  --graph data/evidence_graph.json
~~~

Saved to eval/generated_gpt.jsonl with the actual generating contexts,
document identities, source-page metadata, latency and inference call trace.
Previously completed strategy/backend/question combinations are skipped.
Errors never count as successful answers.

To enable an optional on-disk GPT response cache:
set RAG_GPT_CACHE to data/gpt_responses.sqlite. It caches only text and usage,
not bearer tokens. Keep the file local and protected if the corpus is sensitive.

## Offline evaluation and adaptive routing

~~~bash
# Deterministic paper-level precision@k, recall@k, MRR and nDCG
python -m rag_lab.evaluation.benchmark retrieval --input eval/generated_gpt.jsonl

# Checkpointed GPT judge; one combined rubric call per answer
python -m rag_lab.evaluation.benchmark judge --input eval/generated_gpt.jsonl

# Train a locally executed, non-LLM query router from completed scored rows
python -m rag_lab.routing.train_router \
  --generations eval/generated_gpt.jsonl \
  --scores eval/gpt_judge_scores.jsonl \
  --output data/adaptive_router.joblib
~~~

A lightweight evidence policy runs with every generation, without GPT calls.
It records whether context exists, whether cross-paper questions have distinct
paper provenance, and whether supplied citation IDs are valid. To request a
**conditional extra GPT verification call** when those checks warn, add the
--verify-on-warning flag to the generation command. This option spends more
ChatGPT plan allowance and should not be enabled for bulk benchmarks unless
you are explicitly measuring verification overhead.

The custom GPT judge measures faithfulness, answer correctness, answer
relevance and citation support with a versioned prompt. **These are not
official RAGAS metrics.** The optional RAGAS adapter is in
rag_lab/evaluation/ragas_support.py; validate compatibility on a small subset
before running a large benchmark.

The router trainer requires 25 or more distinct questions with two or more
scored strategies and a meaningful class distribution. It holds out 25 percent
of question IDs and reports holdout strategy classification accuracy. With
insufficient data, routing defaults safely to naive. Only load joblib files
you generated yourself; untrusted pickles are unsafe.

Before reporting CV performance claims, add paper-disjoint testing,
manually verified evidence labels, cross-model judge comparisons and quality/
latency/call-count ablations. Your current historical evaluation data is
insufficient for a defensible claim of model superiority.

## Limitations

- GPT OAuth must be authorized interactively by the user on their own machine.
  CI uses mocks and never spends the user's ChatGPT plan allowance.
- Existing notebooks include experimental paths and incomplete RAPTOR scoring.
- The paper corpus, Chroma store and PyLate index must be built separately.
- Citation ID validity is deterministic; semantic faithfulness requires judged
  or human-verified evaluation.
- GPT-generated answers judged by GPT have possible model-family bias.
- RAGAS releases may need minor version-specific integration adjustments.
- The evidence association graph uses deterministic term extraction, not
  validated theorem or causal relationship extraction.


## Chroma index repair: empty contexts in GPT generation

The original foundation notebook used the literal path
`~/Codes/rag-lab/data/chroma_naive_gemini` without expanding the home
directory. Its 576 embedded chunks may have been written below a directory
**literally named `~`**, depending on the notebook kernel's working directory.

Do not regenerate embeddings or delete indexes before locating the existing one.

~~~bash
cd /home/mohnish/Codes/rag-lab
find . -name chroma.sqlite3 -print
python -m rag_lab.retrieval.chroma_health --search-root .
~~~

Use the location containing **nonzero chunks** in the `langchain` collection.
For example, if it is under the notebooks folder:

~~~bash
python -m rag_lab.evaluation.generate --strategies naive --backends dense \
  --limit 3 \
  --chroma-path 'notebooks/~/Codes/rag-lab/data/chroma_naive_gemini' \
  --output eval/generated_gpt_repaired.jsonl
~~~

Use the actual directory from the diagnostic; the shown path is only an example.
If the populated collection name differs, use `--chroma-collection NAME`.

The generation CLI now fails before any GPT request when the selected Chroma
collection is empty, retries previous empty-evidence attempts rather than
treating them as completed, and excludes zero-evidence attempts from judge
scoring. The naive strategy also avoids calling GPT on empty retrieval results.


## Source provenance and retrieval quality (v2)

Every retrieved passage is now annotated *before* generation using a canonical
paper registry in rag_lab/knowledge/paper_registry.py. The registry is built
from eval/eval_set.json filenames, exact normalized titles and a short list of
audited aliases for PDF filenames that differ from the dataset metadata. It
does not consult a question's gold source_documents when identifying a paper,
and deliberately leaves unknown filenames unresolved rather than inventing
a match. Add any new verified aliases to ALIASES before reporting retrieval
scores. New passage IDs are content-addressed, and generated citations
refer to PDF page numbers starting at 1 rather than the loader's zero-based
page index. A PDF page is not necessarily the same as the printed page number.

### Repair already generated answers (zero GPT and Gemini usage)

~~~bash
python -m rag_lab.evaluation.provenance_repair \
  --input eval/generated_gpt_repaired.jsonl \
  --output eval/generated_gpt_provenance.jsonl
~~~

The old answer strings stay unchanged, including their original citation
format. Source records receive canonical paper IDs, distinct passage IDs,
and legacy citation IDs for independent audit. Originals are NEVER replaced.

Compute paper-aware metrics with no model requests:

~~~bash
python -m rag_lab.evaluation.benchmark retrieval \
  --input eval/generated_gpt_provenance.jsonl \
  --output eval/retrieval_metrics_v2.jsonl
~~~

Metrics now evaluate the original **top-k retrieved chunks**, not a
deduplicated rank list of papers. Report chunk precision@k, distinct-paper
recall@k, MRR@k, and novelty-aware nDCG@k, alongside the proportion of source
chunks with resolvable provenance. If any chunk ID is unknown, the ranking
metrics are null rather than silently treating an unidentified paper as
irrelevant. Outputs have metric version and content fingerprint fields so
old invalid scores are never mistaken for a fresh evaluation.

### Compare retrieval techniques without GPT generation

~~~bash
python -m rag_lab.evaluation.retrieval_compare \
  --modes similarity mmr --k 4 --fetch-k 20 \
  --lambda-mult 0.5 --limit 10 \
  --output eval/retrieval_ablation_v2.jsonl
~~~

This invokes **Gemini query embeddings** for retrieval, but does not call
GPT or regenerate answers. Extend --limit to cover the 63-question dataset.
Compare performance by question type and source coverage. MMR favors
diversity; it is an experimental alternative, not presumed superior to
similarity search. Only promote MMR or other reranking if held-out retrieval
quality improves without unacceptable latency. MMR changes the underlying
retrieved evidence, so an answer-quality comparison would subsequently
require new GPT responses for that separate retrieval configuration.

The judge uses a separate custom GPT rubric; it does not produce RAGAS
metrics unless the separate RAGAS adapter is used. Versioned evaluation
scores should not be compared across prompts or paper registries without
carefully aligning labels and the retrieval corpus.


### Retest after correcting an audited paper filename alias (no API calls)

Do **not** rerun the old retrieval_compare command against the same output:
its resume logic will skip already-completed runs, preserving stale null scores.
The audited XPINN filename is now registered under `xpinn` in
`rag_lab/knowledge/paper_registry.py`. Re-evaluate saved rankings offline:

~~~bash
python -m rag_lab.evaluation.rescore_retrieval \
  --input eval/retrieval_ablation_v2.jsonl \
  --output eval/retrieval_ablation_v2_rescored.jsonl
~~~

This reads only `eval/eval_set.json` and the previous ablation JSONL. It makes
**no Gemini embedding, GPT generation or GPT judging requests**. The CLI prints
recovered/missing provenance counts and per-method means. It refuses to overwrite
existing outputs and raises on conflicting paper IDs or duplicate runs.

Re-running retrieval itself is a *different* experiment and requires Gemini
embeddings: use `--output eval/retrieval_ablation_fresh.jsonl` instead of
appending to the earlier checkpoint. Stored passage IDs that start with
`unknown:` cannot be accurately regenerated from the retrieval-only JSONL,
because that file doesn't include chunk text; offline rescoring leaves these
IDs in place and marks `passage_id_needs_regeneration`. Future freshly retrieved
passages will receive corrected `xpinn:<digest>` IDs automatically.
